# Команда №45 · Digital HR · JanaМен

## Быстрый запуск из GitHub (Windows)
Python 3.10+; для базового запуска pip не требуется.

```powershell
py -3 server.py --port 8018 --no-browser
```

Откройте http://localhost:8018. При первом старте создаются синтетические демонстрационные данные.
Роли: сотрудник, руководитель, HR/администратор. Сгенерированные данные входа смотрите ЛОКАЛЬНО в `data/DEMO-ACCOUNTS.txt`; не коммитьте файл или базу.

### Настройка Gemini
В этой версии для GitHub файла с ключом НЕТ. Создайте его локально:

```powershell
Copy-Item GEMINI_KEY.example.txt GEMINI_KEY.txt
notepad GEMINI_KEY.txt
```

Замените заглушку своим ключом Google AI Studio одной строкой. Сохраните. Не публикуйте ключ.
`py -3 scripts/check_ai.py --local` — чтение настройки без запроса Google.
`py -3 scripts/check_ai.py` — запрос Google, может расходовать токены.
Без ключа остальные разделы доступны, генерация Gemini недоступна.

### Демо для жюри
1. Сотрудник: профиль → новая заявка на отпуск → статус/история.
2. Руководитель: своя команда → согласование. HR: завершение обработки.
3. Сотрудник: изменившийся статус/уведомление; назначенный курс → тест → результат.
4. AI Jana: вопрос о платформе → ответ Gemini с доступными справочными инструкциями.
5. Workspace: общая задача и документы только участникам.

**Ограничение AI:** в текущей версии включён обычный чат с контекстом. Кнопки инструкций не доказывают каждое утверждение. Строгое требование кейса «только по базе, источник, отказ вне базы» не следует считать полностью выполненным без отдельной доработки и приёмки.

Тесты: `py -3 scripts/run_tests.py` — 151 локальный тест, без живого Google.
Архитектура и будущие интеграции: `docs/ARCHITECTURE.md`.
Финальную презентацию добавьте в `presentation/` перед сдачей.

# JanaМен 1.4 iPhone PWA + Gemini — команда 45

Полная платформа Digital HR. Десктопные функции сохранены, добавлена мобильная PWA для iPhone 13: четыре нижние вкладки, safe-area, удобные формы, светлая/тёмная тема, установка из Safari и публичная offline-страница.

## Начало
1. Прочитайте **НАЧНИ_ЗДЕСЬ.txt**: остановите старый сервер, распакуйте в новую папку, перенесите `data/` и свой `GEMINI_KEY.txt`.
2. `START_IPHONE_SERVER.bat` — сервер на `http://localhost:8018` для первой проверки компьютера.
3. Для телефона следуйте **АЙФОН_НАЧНИ_ЗДЕСЬ.txt**: нужен общий HTTPS-адрес. Готового публичного развёртывания в архиве нет.
4. После настройки `JANA_PUBLIC_URL` открывайте **общий HTTPS-адрес на обоих устройствах**, а не localhost. Пример reverse proxy: `Caddyfile.example`.

Подробности Gemini: **ИИ_НАЧНИ_ЗДЕСЬ.txt**. `py -3 scripts/check_ai.py --local` проверяет только настройку; без `--local` выполняет запрос Google, который может расходовать токены.

## Общие данные
Один сервер и одна SQLite-база. Активное приложение опрашивает изменения примерно раз в 3 секунды; на переднем плане после возвращения запрашивает свежие данные. Нет гарантии фоновой синхронизации и push-уведомлений. Нет офлайн-отправки или кеша кадровых данных. Для постоянной работы нужен постоянно включённый HTTPS-сервер.

## ИИ
Прямой Google Gemini REST API, обычный диалог с историей и доступными справочными инструкциями. Нет скрытой подмены ответа выдержкой из базы. Модель автоматически выбирается из доступного списка Google; точное имя показывается после ответа. Ключ хранится на сервере, не в браузере. Локальные аккаунтные запросы не отправляют кадровые записи Google. Не вводите персональные данные и пароли в чат: текст сообщений передаётся провайдеру. ИИ не выполняет кадровые решения и не изменяет базу. Квоты, доступ и правила Google действуют.

## Проверки
`py -3 scripts/run_tests.py` — **151 тест OK**, внешние провайдеры запрещены тестовым запуском. Браузер: 54 проверки вёрстки на 6 размерах + 11 функциональных проверок; обмен статусами между мобильным сотрудником и десктопными руководителем/HR, Workspace, чат через локальную Google-shaped заглушку, офлайн/возврат и защита редактирования при polling.

Актуальный отчёт: `testing/07_IPHONE_1_4.txt`. Эмуляция Chromium, **не физический Safari**. Реальный ключ Google, Windows, Docker build и внешний HTTPS-туннель здесь не проверялись. Не считать это гарантией работы на всех версиях iOS.

## Платформа и ограничения
Профиль, отпуск сотрудник → руководитель → HR, Workspace/задачи/заметки/файлы, Academy, сервисы, адаптация, календарь, уведомления, аналитика и управление. Python 3.10+ stdlib + SQLite. Роли, CSRF, ACL, сессии и история сохранены. База и демо-пароли создаются в `data/` при первом запуске; в архиве их нет.

1С, Documentolog и юридическая ЭЦП не подключены. Это учебный MVP, не сертифицированная промышленная HR-система. Временный туннель открывает страницу входа интернету: только синтетические данные; перед реальным внедрением — аудит и защита инфраструктуры.

Предыдущие отчёты в testing/ и презентация относятся к прежним версиям. Не выдавайте их за актуальные результаты этой сборки.
