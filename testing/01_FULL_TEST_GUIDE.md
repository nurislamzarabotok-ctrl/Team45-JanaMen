# Проверка платформы — команда 45

## Подготовка

- Запускайте из распакованной папки, не из ZIP.
- Скопируйте `data` в резервную папку перед обновлением. Все сценарии ниже — на синтетических данных.
- Три независимых браузерных профиля: сотрудник, руководитель, HR. Адреса/случайный пароль — локальный `data/DEMO-ACCOUNTS.txt`.
- Сначала локальный адрес; телефоны подключайте только после проверки через общий HTTPS.
- Отдельно запустите `python -m unittest discover -s tests -v`. Ожидается 86 тестов, OK.

## A. Вход, аккаунты и кадровые поля

1. На входе не должно быть трёх кнопок деморолей и предзаполненной почты.
2. Неверный пароль → понятная ошибка, кабинет не открывается.
3. Войти сотрудником → профиль доступен для чтения; нельзя изменить должность/остаток обычной формой.
4. «Запросить исправление» → отправить «Уточните должность». HR: «Управление» → запрос виден. Изменить поле в профиле сотрудника, затем отметить запрос обработанным. Сотрудник получает уведомление.
5. HR: создать новый аккаунт сотрудника, указать руководителя. Сохранить временный пароль в приватном месте, не показывать его в Zoom.
6. Войти новым аккаунтом: требуется смена временного пароля. Попытка изменяющего API до смены → 403. Пароль меньше 10 символов или несовпадающее подтверждение → ошибка.
7. После смены открыть Workspace и создать личную задачу. Выйти и войти новым паролем.
8. HR: сбросить пароль этому аккаунту. Старый сеанс должен перестать работать. Новый временный пароль требует смены.
9. Заблокировать аккаунт → вход запрещён. Разблокировать → восстановить доступ. HR не может заблокировать себя или снять с себя роль HR.
10. Попробовать повторную почту → 409. Цикл подчинения руководителей → ошибка.

## B. Отпуск — главный сквозной сценарий

1. Сотрудник → «Мои заявки» → «Новая заявка». Указать будущий непересекающийся период 3 дня и комментарий без ПДн.
2. Проверить включительный расчёт календарных дней; начало/конец считаются днями отпуска.
3. Дата в прошлом, конец раньше начала, превышение показанного остатка → ошибка. Пересечение со своей активной/завершённой заявкой → 409.
4. Отправить корректную заявку. Ожидаются номер, статус «На согласовании», история создания, уведомление.
5. В активном кабинете руководителя заявка должна появиться без F5 приблизительно за 3 секунды плюс задержка сети. Фоновая вкладка может обновиться позже.
6. Открыть заявку и отклонить без причины → 400, статус не меняется. Добавить причину → отказ сохраняется и виден сотруднику.
7. Создать другую заявку, согласовать руководителем. HR получает очередь «Требуют действия». Сотрудник не может согласовать свою заявку, HR не может завершить несогласованную.
8. HR завершает обработку. Сотрудник видит «Обработана HR», все этапы истории, уведомление. Documentolog/1С/ЭЦП не должны ошибочно считаться вызванными.
9. Отдельная новая заявка: до решения изменить даты → история изменения. Отозвать → «Отозвана», последующее согласование недоступно.
10. Сохранить старые исходные даты/версию, параллельно изменить их во втором окне → повторная старая запись отклоняется 409.
11. Добавить TXT/PDF/DOCX-вложение своей заявки; руководитель и HR скачивают. Посторонний пользователь/подмена ID → 404. «Сформировать заявление» скачивает TXT с историей и явным отсутствием ЭЦП.
12. HR создаёт второго руководителя, назначает замещение основному. Замещающий видит заявки команды, после снятия замещения больше не видит.

## C. Workspace и документы

1. Создать общее пространство, добавить другого сотрудника. Создать задачу и назначить участнику, поставить срок/приоритет.
2. Во втором активном кабинете открыть это пространство. Изменить задачу на «В работе», добавить комментарий. Первый кабинет обновляется автоматически.
3. У пользователя вне пространства задача/комментарии не появляются, подмена ID отклоняется сервером.
4. Исключить участника: доступ к пространству/общим задачам/общим файлам исчезает. Исключение не отменяет независимый доступ к собственному файлу или прямую передачу файла — проверяйте все основания доступа.
5. Открыть одну задачу одновременно в двух профилях: после сохранения первого второй со старой версией получает конфликт, а не затирает изменение.
6. Создать личную заметку, изменить её, перезагрузить. Посторонний пользователь её не видит.
7. Загрузить UTF-8 TXT с уникальным словом «тест-накладная-45», передать коллеге. Поиск по слову должен находить файл, по произвольному слову — нет.
8. Проверить DOCX и PDF с текстовым слоем. Для PDF установить `requirements-optional.txt`. Скан/изображение ищутся только по имени, не по содержимому.
9. EXE/HTML/JS → запрет; >2 МБ → ошибка; имя с путями не должно влиять на путь сервера. Хранилище владельца ограничено 30 МБ.
10. Получатель скачивает, но не удаляет чужой файл. Владелец удаляет → ссылка перестаёт работать. Скачивание не должно открывать загруженный HTML как страницу приложения.
11. Ввести `<script>alert(1)</script>` в комментарий: отображается текстом, не выполняется.

## D. Сервисы, адаптация, обучение, календарь и аналитика

1. Создать обращение категории IT → оно попадает HR-диспетчеру. HR назначает ответственного, меняет статус на «В работе», отвечает; автор видит изменения и может закрыть обращение.
2. Другой сотрудник не видит чужого обращения, если не назначен ответственным. HR видит диспетчерскую очередь.
3. HR назначает адаптацию сотруднику. Повторное назначение тому же сотруднику → 409. Из четырёх шагов три отмечаются сотрудником, курс — только через Academy.
4. Academy: материал → «Материал изучен» → ответить на все 6/5 вопросов. Без изучения или части ответов сервер не принимает тест.
5. Верный результат сохраняется. После плохой повторной попытки лучший балл не снижается. Порог 67%; история попыток сохраняется в БД.
6. HR создаёт курс в визуальном редакторе: материал, минимум три вопроса, по три варианта, правильный ответ. Добавить четвёртый вопрос. Назначить сотруднику из HR-кабинета. При назначении появляется уведомление.
7. Календарь: выбрать месяц имеющейся заявки; сотрудник видит свои заявки, руководитель — разрешённые командные, HR — все. Предварительные заявки различаются текстовым статусом. Отклонённые/отозванные не создают отсутствие.
8. Создать пересекающиеся заявки двух сотрудников одной команды: предупреждение в выбранном месяце, но не запрет руководителю принять решение.
9. Аналитика недоступна сотруднику, доступна руководителю/HR в пределах разрешённых данных. Количества сверить со списком. Среднее время показывается только при наличии завершений с историей, рядом размер выборки.
10. Задача со сроком сегодня → одно напоминание за день при открытии. Повторные snapshot не создают дубликаты. Отключение напоминаний не скрывает обычные события.

## E. AI Jana

1. Без ключа задать «Как оформить отпуск?» → точная выдержка + источник, **не** надпись, что LLM вызвана.
2. «Мои заявки» → только собственные статусы. «Мой остаток» → локальный показатель с оговоркой об отсутствии 1С.
3. Вопрос о зарплате/чужих данных/неизвестном правиле → отказ, без выдуманного ответа.
4. Создать новый диалог, задать вопрос, перезайти → история доступна владельцу. Другой аккаунт не получает её по подмене ID. Удалить → диалог исчезает.
5. HR добавляет источник/версию/аудиторию. У сотрудника не должно появляться содержимое HR-источника. При отзыве доступа сохранённая история не должна снова раскрыть источник через API.
6. Для настоящего LLM-вызова: `.env`, перезапуск, `scripts/check_ai.py`. Ключ никуда не печатать. Контрактные тесты не заменяют эту проверку.
7. Включить неверный ключ/недоступный model ID → точная выдержка с понятным уведомлением, не пустой экран и не выдуманная успешная генерация.
8. Проверить каждый язык отдельными вопросами и цитатами. Это ещё не выполнено на реальной модели владельца.
9. 9-й вопрос за минуту → ограничение; дневной лимит и 2 параллельных запроса → безопасный fallback. Не проверяйте платные квоты массовым спамом.

## F. Сеть и восстановление

- При остановке сервера баннер/ошибка; действие не считается отправленным. После возобновления — новый запрос или восстановление соединения.
- При потере интернета PWA не отправляет действия в скрытую очередь, не показывает старую кадровую базу как актуальную.
- Перезапуск сервера завершает сессии, но задачи/заявки/история остаются в SQLite.
- Проверить резервную копию: остановить сервер, скопировать `data/jana.sqlite3`, запустить копию в отдельной папке. Не копировать SQLite во время записи обычным Explorer без остановки.
